# Tessera — Architecture Reference

**Version:** Phase B (2026-09-24)  
**Status:** Living document — update when a new subsystem is added or an ADR changes a key design decision.

---

## 1. System Overview

Tessera is a **multi-tenant Retrieval-Augmented Generation (RAG) API** built with FastAPI. Each tenant has an isolated corpus and vector index. Answers are generated by a LiteLLM-backed LLM and asynchronously evaluated by a Redis-queued judge worker. An A2A agent layer handles multi-turn drafting and orchestration.

## 3. Request Lifecycle — `/ask`

```
1. Request received → API auth middleware validates HMAC Bearer token
2. Rate limiter checks Redis fixed-window counter (per user_id)
3. Tenant governor checks Redis per-tenant counters (token budget, request cap)
4. Cost observability: over_cap() check (advisory)
5. Semantic cache lookup (in-process, SHA-256 keyed on tenant+query+chunks+model)
   └─ HIT → return cached answer immediately
6. RAG router selects strategy (adaptive, dense, sparse, hybrid, agent)
7. RAG pipeline:
   a. Tenant context sets per-request Chroma index dir via contextvars
   b. Retriever (dense / sparse / hybrid) fetches candidate chunks
   c. Cross-encoder reranker filters to top-k (threshold 0.90 — ADR-003)
   d. Generator calls LiteLLM → deepseek-flash (default) or gpt-4o-mini
   e. Answer guard validates response (blocked phrases, quality thresholds)
8. Cost: record() adds estimated_usd to in-process accumulator
9. RAG quality signals: record_rag_signals() writes rag_quality record to analytics.jsonl
10. Response assembled: AskResponse (15 fields)
11. Judge queue: LPUSH job to Redis queue (at-most-once — ADR-021)
12. Analytics log: ask record appended to logs/analytics.jsonl
13. Response returned to caller
```

Judge worker (separate process, async):
```
1. BLPOP job from Redis queue
2. Run DeepEval + LLM judge on question/answer/context
3. Write eval result to judge store (SQLite)
4. Failed jobs → DLQ (best-effort Redis LPUSH)
```

## 4. Tenant Isolation

| Layer | Mechanism |
|-------|-----------|
| Vector store | Per-tenant Chroma directory (`data/chroma/<tenant>/`), set via `contextvars` in `tenant_context.py` |
| Corpus files | Per-tenant directory (`data/corpus/<tenant>/`) |
| Rate limiting | Per-user Redis key (`rl:<user_id>`) |
| Token/request budget | Per-tenant Redis counter (`tg:<tenant>:tokens`, `tg:<tenant>:requests`) — ADR-016 |
| Semantic cache | Cache key includes tenant as first element |
| Auth DB | Single SQLite (`auth.db`); queries always filter by `user_id` |
| Judge results | Single SQLite (`judge_store.db`); queries filter by `user_id` |
| Analytics log | Single JSONL; records include `tenant` field |

## 5. Persistence Inventory

| Store | Technology | Location | What lives there |
|-------|------------|----------|-----------------|
| Vector index | ChromaDB | `data/chroma/<tenant>/` | Embeddings + metadata per tenant |

| Judge results | SQLite | `judge_store.db` | Eval pass/fail per request |
| A2A checkpoints | SQLite or Redis (configurable) | `checkpoints.db` / Redis hash | Agent conversation state |
| Rate limit counters | Redis | `rl:<user_id>` | Fixed-window request counts |
| Tenant governance | Redis | `tg:<tenant>:*` | Per-tenant token + request counters |
| Judge queue + DLQ | Redis | `judge_queue`, `judge_dlq` | Pending + failed eval jobs |
| Semantic cache | In-process dict | — | Recent answer cache (lost on restart) |
| Cost accumulator | In-process float | — | Daily spend per process (lost on restart) |
| Analytics log | JSONL file | `logs/analytics.jsonl` | Per-request ask + rag_quality records |

## 6. Resilience Mechanisms

| Mechanism | Implementation | Default config | Failure mode |
|-----------|---------------|----------------|--------------|
| Rate limiter | Redis fixed window | 100 req/min/user | Fail-open on Redis loss (ADR-015) |
| Tenant governor | Redis counters | Configurable per-tenant caps | Fail-closed on Redis loss (ADR-016) |
| Circuit breaker | In-process (tenacity-like) | 5 failures → open | Blocks LLM calls; auto-resets after cooldown |
| Bulkhead | asyncio.Semaphore | `MAIN_POOL_SIZE=10` | 429 when full |
| Embedding resilience | Retry + fallback | 3 retries, model fallback | Exception propagated if all fail |
| Judge queue cap | Redis LPUSH guard | `JUDGE_QUEUE_MAX_DEPTH=100` | `/ask` returns 429 when exceeded |
| DLQ | Redis LIST | unbounded (see D5 in threat model) | Failed jobs accumulate; manual drain |
| Cost cap | In-process check | `TESSERA_DAILY_SPEND_USD_CAP` (optional) | Advisory only; not atomic under parallel load (see D6) |

## 8. Retrieval Strategies

| Strategy | Route key | Description |
|----------|-----------|-------------|
| `adaptive` | default | Selects dense/sparse/hybrid based on query characteristics |
| `dense` | `dense` | Cosine similarity search on OpenAI embeddings |
| `sparse` | `sparse` | BM25-style keyword retrieval |
| `hybrid` | `hybrid` | Reciprocal rank fusion of dense + sparse results |
| `agent` | `agent` | Multi-turn A2A drafter-judge pipeline with checkpointing |

All strategies pass retrieved chunks through the cross-encoder reranker (threshold 0.90) before generation.

## 9. Key Design Decisions

See `docs/adr/README.md` for the full ADR index. Highlights:

| ADR | Decision | Impact |
|-----|----------|--------|
| ADR-003 | Cross-encoder reranker at 0.90 threshold | Quality/latency trade-off |
| ADR-007 | Redis queue for judge jobs | Decouples eval from /ask latency |
| ADR-015 | Rate limiter fail-open | Availability over strict rate enforcement |
| ADR-016 | Tenant governance fail-closed | Correctness over availability for budget enforcement |
| ADR-018 | In-process cost accumulator | Simple; not atomic across replicas |
| ADR-019 | Fail-closed shadow eval promotion | New index only promoted if measurably better |
| ADR-020 | Separate rag_quality analytics record | Decoupled from ask record; optional/fail-safe |
| ADR-021 | At-most-once judge queue delivery | Simple; upgrade path documented for at-least-once |

## 10. Deployment

Development:
```bash
uv run uvicorn src.api.app:app --host 127.0.0.1 --port 8000 --reload
```

Production (Kubernetes):
- `k8s/deployment.yaml` — tessera-api (2 replicas) + tessera-judge-worker (1 replica)
- `k8s/service.yaml` — ClusterIP on port 80 → 8000
- `k8s/hpa.yaml` — HPA on queue depth for judge worker auto-scaling
- Secrets: `tessera-secrets` (REDIS_URL, API keys, SECRET_KEY)
- Config: `tessera-config` (TESSERA_DAILY_SPEND_USD_CAP, CHECKPOINTER_BACKEND)

Load testing:
```bash
locust -f loadtests/locustfile.py --headless -u 50 -r 5 --run-time 5m --host http://127.0.0.1:8000
```
