# ADR-018: Centralised Cost Observability Module

**Status**: Accepted  
**Date**: 2026-09-24  
**Deciders**: Engineering team

---

## Context

Cost estimation for LLM calls was scattered across two places:
- `src/rag/llm.py` -- `_USD_PER_1M_TOKENS`, `_estimate_usd`, `record_spend`, `spend_so_far`
- `src/api/app.py` -- `DEEPSEEK_CHAT_USD_PER_1M_TOKENS_ESTIMATED`, inline cost formula at lines 62-63 and 680/814

This duplication means pricing updates require changes in multiple files, and `estimated_cost_usd`
in the AskResponse uses a different constant than the LLM-layer spend guard, creating drift risk.

---

## Decision

Create `src/observability/cost.py` as the single source of truth for:

1. **`RATES`** -- per-model USD/1M-token table (replaces both `_USD_PER_1M_TOKENS` in llm.py and
   the inline constants in app.py)
2. **`estimate_usd(model, prompt_tokens, completion_tokens)`** -- canonical cost formula
3. **`record(usd)`** / **`spend_so_far()`** / **`reset()`** -- thread-safe session accumulator
4. **`daily_cap()`** / **`over_cap()`** -- env-var-driven hard cap check

`src/rag/llm.py` continues to import `RATES` and the accumulator functions from this module
so existing tests and the spend-guard path work without changes. `app.py` inline constants
remain as legacy fallbacks until a follow-up PR migrates them; they are marked with a
`# TODO(ADR-018): replace with observability.cost.RATES` comment.

---

## Consequences

**Positive**
- Single file to update when provider pricing changes.
- `over_cap()` is importable from anywhere without a circular import (no FastAPI dependency).
- Test helpers can call `reset()` to zero the accumulator between test cases without touching
  `src/rag/llm.py` internals.

**Negative / Accepted**
- `src/rag/llm.py` still carries its own copy of `_USD_PER_1M_TOKENS` (not yet removed) to
  avoid a breaking change in the middle of this sprint. A follow-up will make llm.py import
  from observability.cost and remove the duplicate.
- The accumulator is per-replica; cross-replica spend aggregation is still a known gap
  (see docs/COST_MODEL.md section 6).

---

## Alternatives Considered

| Option | Why rejected |
|---|---|
| Keep cost constants in llm.py | Continued drift between llm.py and app.py inline constants |
| Centralise in config.py | config.py already large; observability concerns are distinct |
| Use Langfuse for cost tracking | External service; adds latency and availability dependency |
