# ADR-017 — Five-Threshold Quality Gate

**Status:** Accepted  
**Date:** 2026-09-23

## Context

The existing CI evaluation gate checked only two quality metrics — mean relevancy (≥ 0.6) and mean correctness (≥ 0.5). This left latency, error rate, and cost unguarded: a regression in any of these could ship undetected.

Senior RAG deployments require a holistic merge-blocking gate that covers both quality metrics and operational metrics in a single structured pass/fail verdict.

## Decision

Extend `evals/gate.py` to check five thresholds:

| Check | Metric key | Operator | Default threshold |
|-------|-----------|----------|-------------------|
| 1 | `aggregates.mean_relevancy` | ≥ | 0.60 |
| 2 | `aggregates.mean_correctness` | ≥ | 0.50 |
| 3 | `performance.latency_p95_ms` | ≤ | 3000 ms |
| 4 | `performance.error_rate` | ≤ | 0.05 (5 %) |
| 5 | `performance.cost_per_request_usd` | ≤ | $0.01 |

All five thresholds are env-var overridable (`MIN_MEAN_RELEVANCY`, `MIN_MEAN_CORRECTNESS`, `LATENCY_P95_MAX_MS`, `ERROR_RATE_MAX`, `COST_PER_REQUEST_MAX_USD`) and live in `src/rag/config.py` as the single source of truth.

The gate returns a structured result:

```json
{
  "passed": true,
  "checks": [
    {"name": "mean_relevancy", "value": 0.917, "threshold": 0.6, "op": "ge", "passed": true, "skipped": false},
    ...
  ]
}
```

When a performance field is absent from the report (e.g. the run_eval script does not yet emit latency), the check is marked `skipped: true` and treated as passing. This allows incremental adoption: quality checks block immediately; operational checks block only once the eval pipeline emits the corresponding field.

## Alternatives Considered

**Hard-fail on missing fields:** Would require all five fields to be present before the gate can run. Rejected because it forces a bigger simultaneous change to `run_eval.py` and blocks CI during the transition.

**Separate gates per concern:** A latency gate and a quality gate as separate CI steps. Rejected because it multiplies CI jobs and makes the single structured verdict harder to consume.

## Consequences

- The gate is backward-compatible: existing reports without `performance` fields pass the new checks (skipped).
- Adding latency/cost instrumentation to `run_eval.py` in a future phase will automatically activate the corresponding gate checks without any gate code change.
- All five thresholds can be tightened per-environment via env vars without code changes.
