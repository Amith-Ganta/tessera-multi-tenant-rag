# ADR-022 — A2A Service Authorization Boundary

**Status**: Accepted  
**Date**: 2026-09-24  
**Context**: Tessera Hardening Pass — Item 1 (Phase 1, P0 Security)

---

## Context

Tessera's Drafter and Judge agents run as standalone FastAPI servers (default
ports 8001 and 8002).  They accept JSON-RPC 2.0 `message/send` requests whose
skill parameters — including `tenant_slug` — arrive in the request body as
caller-supplied metadata.

Before this ADR, no service-to-service authentication existed.  Any network
principal that could reach those ports could supply an arbitrary `tenant_slug`
and retrieve documents from any tenant's corpus without holding a valid Tessera
user token.  This violates the tenant isolation guarantee documented in
ADR-013.

The `/ask` endpoint is **not** affected: it derives `tenant` from the
authenticated user's session token via `auth.tenant_slug(user_id)` and the
`A2ASupervisor` call inside `_run_a2a()` already passes the correct tenant.
The gap is on the **receiving side** of the Drafter/Judge agents — they cannot
tell whether the caller is the authorised supervisor or a rogue client.

## Decision

1. **Shared-secret header**: a new env var `TESSERA_A2A_SERVICE_TOKEN` holds a
   secret string provisioned at deploy time (K8s Secret / `.env` file).

2. **Agent enforcement**: `make_a2a_app()` (in `src/agents/a2a_protocol.py`)
   gains an `authenticate: bool = True` parameter.  When `True` and the env
   var is set, the handler checks the inbound `X-Tessera-Service-Token` header
   using `hmac.compare_digest` (constant-time).  A missing or wrong header
   returns HTTP 401 **before** dispatching to the skill — fail-closed.

3. **Supervisor injection**: `A2AJsonRpcClient.send_message()` reads the env
   var and injects the header on every outbound call when the token is
   configured.

4. **Dev / test mode**: when `TESSERA_A2A_SERVICE_TOKEN` is not set the check
   is skipped and a `WARNING` is logged.  This keeps isolated local runs
   functional without requiring secrets in every developer environment.  CI and
   production must set the env var.

5. **Service module**: `src/auth/service_auth.py` is the single source of truth
   for the header name, env var key, and verification logic.

## Alternatives Considered

| Option | Reason not chosen |
|--------|-------------------|
| mTLS between supervisor and agents | Requires cert provisioning per service; high operational overhead for an internal cluster boundary |
| JWT with short-lived tokens | Overkill for a single-cluster deployment; token rotation adds complexity without proportional security gain |
| Network policy (firewall) only | Defence-in-depth requires an application-layer check; network policy alone is insufficient if agents are ever exposed on a shared namespace |
| Per-tenant keys | Tenant metadata must still be trusted from the body; a single service-level gate is the correct first layer |

## Consequences

**Good**
- Standalone Drafter/Judge servers no longer accept unauthenticated `tenant_slug`
  overrides from arbitrary callers.
- Zero external dependencies; uses only stdlib `hmac`.
- Backward-compatible: dev environments without the env var continue to work
  (with a logged warning).

**Neutral**
- Does not prevent the *supervisor* from targeting a tenant it should not;
  the supervisor receives `tenant` from the already-authenticated `/ask` path
  so this is not an additional attack surface.

**Risk / residual**
- The shared secret does not prove *which* service is calling — only that the
  caller knows the secret.  If the secret leaks, any process on the cluster
  can impersonate the supervisor.  Rotate `TESSERA_A2A_SERVICE_TOKEN` on any
  suspected exposure.
- This ADR does not address authorization at the *document* level inside a
  tenant corpus.  See ADR-013 for tenant isolation scope.
